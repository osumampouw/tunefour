The Client & Electron

Reading apps/client — the Electron kiosk that runs on each mini-PC and drives a TV. It's a web page wrapped in a native, locked-down, full-screen window.

A browser + Node, fused into a desktop app

Electron's two-process model

Electron bundles a Chromium browser and Node.js into one desktop app. Every Electron app has two kinds of processes:

ProcessWhat it isIn our repo
Main (Node.js)Controls the app lifecycle, creates windows, full OS access.src/main.ts — the entry point (package.json → "main": "dist/main.js")
Renderer (Chromium)The actual web page shown inside a window.static/index.html
Mental model main.ts is the controller (opens/locks the window, talks to the OS); the HTML is the screen (what plays on the TV). Apps you use daily — VS Code, Slack, Discord — are built the same way.

src/main.ts — the main process

import { app, BrowserWindow } from 'electron';
import * as path from 'node:path';
import { DeviceStatus } from '@tunefour/shared-types';
  • app — Electron's application-lifecycle object (fires ready/activate/quit events).
  • BrowserWindow — creates a native OS window that renders web content.
  • node:path — Node's built-in path module; the node: prefix explicitly means "the Node builtin." The main process runs in Node, so @types/node applies here just like the server.

Creating the window

function createKioskWindow(): void {
  const win = new BrowserWindow({
    fullscreen: true,
    kiosk: true,
    backgroundColor: '#0b1020',
    webPreferences: {
      contextIsolation: true,
      sandbox: true,
    },
  });

  void win.loadFile(path.join(__dirname, '..', 'static', 'index.html'));
}
OptionWhy
fullscreen: true, kiosk: trueKiosk mode — fills the screen, no window chrome, locked so a passerby can't minimize/close it or escape to the desktop. Exactly what a signage TV needs.
backgroundColor: '#0b1020'The window background before content paints — a fail-safe touch that avoids the white startup flash, so you see the brand's dark background, never a blank white screen.
contextIsolation: trueWalls the web page's JS off from Electron/Node internals — a compromised page can't reach require/filesystem.
sandbox: trueRestricts the renderer's OS access.
Why the security flags matter here Later phases render user-authored HTML on screen (inside a sandboxed iframe). contextIsolation + sandbox are the "secure by default" settings that ensure such content can never touch the OS. Set them from day one.

The loadFile path trick

path.join(__dirname, '..', 'static', 'index.html')

At runtime __dirname is apps/client/dist/ (where the compiled main.js lives). .. goes up to apps/client/, then into static/index.html. Why up-and-over? Because tsc compiles src/ → dist/ but does not copy static/ — the HTML stays at apps/client/static/, so we navigate from dist back up to reach it. (void because loadFile returns a Promise we intentionally don't await.)

Lifecycle events

app.whenReady().then(() => {
  createKioskWindow();
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createKioskWindow();
  });
});
  • app.whenReady() — Electron must finish initializing before you can create a window; this Promise resolves when it's ready. Then we open the kiosk window.
  • app.on('activate', ...) — a macOS convention (clicking the dock icon with no windows open recreates one). Harmless boilerplate on Windows.
app.on('window-all-closed', () => {
  // On a kiosk we keep the process alive; a watchdog relaunches on crash.
  if (process.platform !== 'darwin') app.quit();
});
Placeholder behavior Apps normally quit when the last window closes. For a real kiosk we'll change this — the process should stay alive, and a watchdog relaunches it on crash (fail-safe design). This is the default template for now.

static/index.html — the fallback screen

<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; style-src 'unsafe-inline'" />
  • This is the page shown on the TV. Right now it's the branded fallback screen ("Tunefour — Phase 0 scaffold") — the fail-safe concept: when nothing is scheduled (or something fails), show this, never a blank/error screen.
  • The CSP (Content-Security-Policy) tag is more hardening: default-src 'self' means the page may only load resources from itself (no arbitrary remote scripts), and style-src 'unsafe-inline' permits the inline <style> block.

Phase 0 now, vs. what comes later

This is the hello-world kiosk — it opens a locked full-screen window showing a static screen. Later phases add the real substance:

LaterWhat it adds
Content rendererPlays images / video / HTML playlists on the screen.
Local cache + manifest syncOffline-first reconciliation: download, checksum, atomic swap, rollback.
Watchdog heartbeatDetects crash/white-screen and relaunches — auto-recovery.
Reminder from setup We set allowBuilds: electron: false, so Electron's runtime binary isn't downloaded — the client compiles but won't launch here. On a real dev machine flip it to true (or pnpm approve-builds) and pnpm --filter @tunefour/client dev opens the window (it runs tsc then electron ., loading dist/main.js).

ORM & Migration Tool — Decision

Choosing how the NestJS server talks to PostgreSQL for Tunefour. Compares Prisma, Drizzle, and TypeORM against our needs.

Recommendation: Prisma ✅ (rationale below)

What we're deciding, and the vocabulary

Our source of truth is PostgreSQL (a SQL database). The server needs to read and write it from TypeScript. Two related jobs:

  • ORM (Object–Relational Mapper): lets you work with database rows as TypeScript objects instead of hand-writing SQL strings. You call db.device.findMany() and it generates the SQL, runs it, and gives you typed results.
  • Migrations: version-controlled, incremental changes to the database structure (add a table, add a column). Like Git commits for your schema — so every environment (your laptop, CI, production) can be brought to the same shape reproducibly. All three tools handle this.
Coming from raw Node + SQL If you've written pg.query("SELECT * FROM ...") by hand, an ORM removes the stringly-typed SQL and the manual mapping of rows to objects — and gives you autocomplete + compile-time checking on your queries. You can still drop to raw SQL when you need to.

Prisma Recommended

You define your data model in a dedicated schema.prisma file (its own small language). Prisma generates a fully typed client and manages migrations from that schema.

// schema.prisma — the single source of truth for your data model
model Device {
  id        String   @id @default(uuid())
  name      String
  office    Office   @relation(fields: [officeId], references: [id])
  officeId  String
  createdAt DateTime @default(now())
}
// Fully typed query — autocomplete on every field, typed result:
const devices = await prisma.device.findMany({ where: { officeId } });

Strengths

  • Best-in-class developer experience & docs — the schema is readable, errors are clear, and the guides are excellent for newcomers.
  • Excellent migrations — prisma migrate dev diffs your schema and writes the SQL migration for you; prisma studio is a free GUI to browse data.
  • Strong type-safety without you writing the types.
  • First-class NestJS recipe in the official Nest docs.

Trade-offs

  • Separate schema language (not plain TS) — one more small syntax to learn, though it's simple and well-documented.
  • Some very advanced/complex SQL is done via its $queryRaw escape hatch rather than the fluent API.

Drizzle Strong alternative

A lightweight, "SQL-first" ORM. You define the schema in plain TypeScript, and its query builder mirrors SQL closely. Types are inferred — no code generation step at runtime.

// schema in plain TypeScript
export const devices = pgTable('devices', {
  id: uuid('id').defaultRandom().primaryKey(),
  name: text('name').notNull(),
  officeId: uuid('office_id').references(() => offices.id),
});

// query builder reads like SQL:
const rows = await db.select().from(devices).where(eq(devices.officeId, officeId));

Strengths

  • Very close to SQL — if you like knowing exactly what query runs, there's little "magic." Great for the hand-tuned schedule query.
  • Lightweight & fast, schema is just TypeScript, excellent inferred types.

Trade-offs

  • Steeper if you don't already know SQL well — it assumes more SQL fluency, which is a bigger ask while you're also learning TS.
  • Younger ecosystem than Prisma/TypeORM (growing fast, but fewer tutorials/answers).

TypeORM The classic

The long-standing Node ORM. Uses decorators on classes to define entities — the same decorator style as NestJS itself, so it feels native to Nest.

@Entity()
export class Device {
  @PrimaryGeneratedColumn('uuid') id: string;
  @Column() name: string;
  @ManyToOne(() => Office) office: Office;
}

Strengths

  • Stylistically matches NestJS (decorators/classes); it's the ORM used in Nest's own database docs.
  • Mature, feature-rich, large community.

Trade-offs

  • Weaker type-safety than Prisma/Drizzle — some queries return loosely-typed results.
  • Migrations & some behaviours have historically been finicky (auto-generation quirks, sharp edges), which is rough while you're learning.

Recommendation

Use Prisma for Tunefour ✅

Given that you're learning the stack, Prisma wins on the two criteria that matter most right now: gentlest learning curve and outstanding docs, while still giving excellent type-safety and the smoothest migration workflow. Its official NestJS recipe means Phase 1 integration is a well-trodden path, and prisma studio gives you a free GUI to see your data as you build — a real help while the schema is forming in your head.

When we'd reconsider: if we later hit a performance-critical query the fluent API handles awkwardly, we use Prisma's raw-SQL hatch for that one query — no need to switch tools. If this were a SQL-expert team optimizing for minimal abstraction, Drizzle would be the pick. TypeORM only if we specifically wanted the decorator-native Nest style and accepted weaker typing.
